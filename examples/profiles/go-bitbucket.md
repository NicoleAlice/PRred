# pr-ready profile

Invented example: a Go service on Bitbucket with Jira issues, SQL access code generated by sqlc and a project that forbids AI-written PR descriptions. Copy it to `.pr-ready/profile.md` only as a starting point; `pr-setup` builds the real one from your repo.

## Platform

- host: bitbucket
- tracker: Jira
- stack tool: plain branches

## Project rules

- contributing: CONTRIBUTING.md
- pr template: .bitbucket/pull_request_template.md
- commit format: Jira key first, e.g. "PARCEL-42 add retry to label printing" (observed in history)
- agent rules: AGENTS.md
- ai_description: forbidden
  > "Write the pull request description yourself; do not paste generated text" (CONTRIBUTING.md, section Pull requests)
- ai_disclosure: required-in-description
  > "If an assistant wrote part of the change, say which part in the description" (CONTRIBUTING.md, section Pull requests)
- prior_approval: not-required
  > "Small fixes can go straight to a pull request; open an issue first for new features" (CONTRIBUTING.md, section Process)

## Base branch

- base: develop

## Commands

- setup: `go mod download`
- reproduce CI: `make ci`
- tests: `go test ./...`
- build: `go build ./... && go vet ./...`
- generated check: `sqlc generate && go mod tidy && git diff --exit-code internal/store/sqlcdb go.mod go.sum`

## Generated files

- `internal/store/sqlcdb/**` (regenerated by `sqlc generate` from `internal/store/queries/*.sql`; header "Code generated by sqlc. DO NOT EDIT.")
- `**/*_mock.go` (header "Code generated by MockGen. DO NOT EDIT.")

## Budget

- max_lines: 400

## Risk paths

- `internal/auth/**`
- `internal/store/migrations/**`
- `bitbucket-pipelines.yml`
- `api/parcel.proto`

## Known traps

| Symptom | Cause | What to do |
|---|---|---|
| Tests pass locally, CI reports a data race | CI runs `go test -race -count=1 ./...` inside `make ci` | Run `make ci`, not a plain `go test` |
| CI fails on `go.mod` or `go.sum` diff | A new import without `go mod tidy` | Run the generated check above before pushing |
