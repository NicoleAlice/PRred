# pr-ready profile

Invented example: a Node.js API on GitLab with a CI pipeline, a generated GraphQL client and a project that asks for an AI trailer on commits. Copy it to `.pr-ready/profile.md` only as a starting point; `pr-setup` builds the real one from your repo.

## Platform

- host: gitlab
- tracker: GitLab issues
- stack tool: plain branches

## Project rules

- contributing: CONTRIBUTING.md
- pr template: .gitlab/merge_request_templates/Default.md
- commit format: conventional commits (observed in history)
- agent rules: AGENTS.md
- ai_description: allowed
  > "You may draft merge request text with an assistant, as long as you have read and can defend every line" (CONTRIBUTING.md, section Assistants)
- ai_disclosure: required-in-trailer
  > "Commits made with an assistant end with an `Assisted-by:` trailer naming the tool" (CONTRIBUTING.md, section Assistants)
- prior_approval: not-required
  > "Bug fixes and small improvements do not need an issue first" (CONTRIBUTING.md, section Workflow)

## Base branch

- base: main

## Commands

- setup: `npm ci`
- reproduce CI: `npm run lint && npm test -- --ci && npm run build`
- tests: `npm test`
- build: `npm run build`
- generated check: `npm run codegen && git diff --exit-code src/graphql/generated`

## Generated files

- `src/graphql/generated/**` (regenerated by the `generated check` CI step)
- `**/*.snap` (.gitattributes: `*.snap linguist-generated`)

## Budget

- max_lines: 500

## Risk paths

- `src/auth/**`
- `src/middleware/session*.ts`
- `db/migrations/**`
- `.gitlab-ci.yml`

## Known traps

| Symptom | Cause | What to do |
|---|---|---|
| Lint passes locally, fails in the pipeline | The pipeline runs `npm ci` from the lockfile; a local `node_modules` had a newer plugin | Run the `setup` step (`npm ci`) before reproducing CI |
| Snapshot tests fail only in CI | The CI image sets `TZ=UTC`; the dev machine does not | Run the tests with `TZ=UTC` |
