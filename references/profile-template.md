# pr-ready profile

Created by `pr-setup`, reviewed by the dev before saving. Saved as `.pr-ready/profile.md` in the target repo. Other skills read it; without it they detect on the fly and suggest running `pr-setup`.

Machine-read parts: the `##` headings below (exact names), the bullets in `Generated files` and `Risk paths` (a glob inside backticks at the start of the bullet), `max_lines:` in `Budget`, and the three policy fields in `Project rules`. The skills also read the `Commands` keys by their exact names (`setup:`, `reproduce CI:`, `tests:`, `build:`, `generated check:`), each followed by a command in backticks or `none found`. Everything else is for humans and agents. Keep a `##` heading for each section, and put no other bullet starting with a backtick in `Generated files` or `Risk paths`.

## Platform

- host: github
- tracker: none
- stack tool: plain branches

## Project rules

- contributing: CONTRIBUTING.md
- pr template: .github/pull_request_template.md
- commit format: conventional commits (observed in history)
- agent rules: AGENTS.md
- ai_description: allowed
  > "AI-written text is welcome if the author has read it" (CONTRIBUTING.md, section Tooling)
- ai_disclosure: none
  > "Contributors need not mention the tools they used" (CONTRIBUTING.md, section Tooling)
- prior_approval: not-required
  > "Small fixes may be sent without an issue" (CONTRIBUTING.md, section Process)

Each policy field needs the quote it came from, on an indented line under it. Allowed values:

- `ai_description`: allowed | forbidden | unclear
- `ai_disclosure`: none | required-in-description | required-in-trailer | forbidden-trailer | unclear
- `prior_approval`: required | not-required | unclear

An `unclear` value, or a missing profile, means the safe option: `pr-write` delivers the facts list and asks the dev whether and how to declare AI use.

## Base branch

origin/HEAD target, else `main`, else `master`, else the dev says.

- base: main

## Commands

- setup: `pip install -r requirements-dev.txt`
- reproduce CI: `make ci`
- tests: `make test`
- build: `make build`
- generated check: `make generate && git diff --exit-code`

`setup:` holds the dependency install or restore steps CI runs (`pip install`, `npm ci`, `dotnet restore`, `bundle install` and the like); they never go in `reproduce CI:`. `pr-prove` runs `reproduce CI:` on its own, but asks the dev before running `setup:`, because installing changes the environment and needs the network.

## Generated files

Globs that do not count toward the line budget and must match what the build generates.

- `src/api/generated/**` (regenerated by the `generated check` CI step)
- `**/*.pb.go` (header "Code generated ... DO NOT EDIT")

## Budget

- max_lines: 500

Hand-written lines are added plus removed against the merge-base, excluding generated files, lockfiles, vendor and binaries. Tests count. A rename counts only its changed lines.

## Risk paths

Globs that force the "risky" level.

- `**/auth*/**`
- `**/migrations/**`
- `.github/workflows/**`
- `openapi*`

## Known traps

| Symptom | Cause | What to do |
|---|---|---|
| Local tests pass, CI fails on line endings | Windows checkout differs from the Linux build only in CR/LF | Compare generated files ignoring line endings |
